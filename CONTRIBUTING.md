# Contributing to Wanderly

Thanks for helping make unfinished thinking feel safe and useful.

## Before opening a PR

1. Open an issue for new product behavior or a large refactor.
2. Keep the capture flow short and understandable.
3. Do not add a model provider API key to client code, commits, screenshots, or examples.
4. Test the changed flow in a browser and run `node --check` on any JavaScript file.

## What we value

Prefer small, reversible changes. When proposing AI behavior, include the exact user problem, the question the AI should ask, and what the user can do with the answer. Avoid adding dashboards, gamification, or automation unless they clearly improve the capture-to-clarity loop.

## Pull requests

Describe the user problem, the behavior you changed, and how you verified it. Screenshots or a short recording are welcome for UI changes.
