# Contributing to Wanderly

Thanks for helping make the irregular parts of a day harder to forget.

## Before opening a PR

1. Open an issue for new product behavior or a large refactor.
2. Keep the capture flow to one line and a deadline.
3. Do not commit API keys, including in screenshots or examples.
4. Run `swift test` in `WanderlyCore/`, then build for both iOS Simulator and macOS (commands in [CLAUDE.md](CLAUDE.md)).

## What we value

Prefer small, reversible changes. When you propose AI behavior, include the exact user problem, the question the AI should ask, and what the user can do with the answer. Avoid dashboards, gamification, or extra automation unless they clearly improve the capture → refine → finish loop.

## Pull requests

Describe the user problem, the behavior you changed, and how you verified it. Screenshots or a short recording are welcome for UI changes.
